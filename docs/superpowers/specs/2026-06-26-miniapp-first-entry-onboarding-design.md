# 小程序首次进入 Onboarding 设计

## 背景

Hestia 当前项目形态为 Web 端、小程序端和服务端。小程序已经具备 onboarding 草稿保存、提交生成初版报告、报告读取和首页空状态能力，但首次进入系统时还没有完整引导流程。

本设计定义小程序首版 onboarding：采用“多步卡片 + 少量快捷选项”，以半强制方式推动用户完成最小建档，同时允许用户先进入主界面浏览。

## 目标

- 用户首次进入小程序时，优先进入轻量 onboarding，而不是直接看到空首页。
- 用户可以跳过 onboarding，但首页、报告和衣橱页要明确提示继续建档。
- 用最少信息跑通第一版核心闭环：目标、场景/禁忌、基础特征、核心衣橱、生成初版报告。
- 保持表达中性、具体、可行动，不制造外貌焦虑。

## 非目标

- 不把照片上传作为首版必填项。
- 不做完整衣橱库存管理。
- 不做电商商品链接或 SKU 推荐。
- 不做相貌对比或“你像某明星”的结论。

## 首次进入策略

小程序启动后应根据用户状态决定入口：

1. 无 token：自动执行开发期登录或正式登录，拿到用户会话。
2. 已有初版报告：进入首页。
3. 无初版报告，但有 onboarding 草稿：进入 onboarding，并恢复到草稿对应步骤。
4. 无初版报告且无草稿：进入 onboarding 欢迎页。

用户在欢迎页可以选择“先逛逛”。跳过后进入 tab 主界面，但主界面需要展示继续建档入口。

## Onboarding 流程

### 1. 欢迎页

目的：降低心理负担，说明这不是一次性测评。

主文案方向：

“我会先用 3 分钟了解你的目标、场景和几件常穿单品，生成第一版可执行形象建议。”

操作：

- 开始建档
- 先逛逛

### 2. 变美目标

交互：快捷多选 + 可选补充输入。

快捷选项：

- 通勤更有气质
- 拍照更上镜
- 约会更好看
- 日常更清爽
- 减少穿搭纠结
- 想换一种风格

补充输入：

“还有什么具体想改变的？”

数据映射：

- `style_goal.goals`

### 3. 场景与禁忌

交互：两组快捷多选 + 可选补充输入。

场景快捷选项：

- 工作日通勤
- 见客户/面试
- 约会
- 周末出门
- 拍照/旅行
- 重要活动

禁忌快捷选项：

- 不要太甜美
- 不要太成熟
- 不要紧身
- 不要复杂
- 不要显廉价
- 不要太高调

数据映射：

- `style_goal.scenarios`
- `style_goal.avoidances`

### 4. 基础特征

交互：轻量输入，全部可跳过。

字段：

- 身高
- 发型/发量备注
- 身材比例或穿衣困扰
- 肤色/妆容习惯

提示文案：

“这些信息只用于让建议更贴近你，不填写也可以继续。”

数据映射：

- `basic.height_cm`
- `basic.hair_notes`
- `basic.body_notes`
- `basic.skin_notes`

### 5. 核心衣橱

交互：至少添加 1 件常穿单品。

单品字段：

- 名称
- 类别：上衣、下装、外套、鞋、包、配饰
- 颜色

操作：

- 继续添加一件
- 先用这些生成报告

数据映射：

- `wardrobe.items`

照片上传可以作为弱入口出现，但不阻塞生成报告。首版文案可以是：“也可以上传衣橱照片，稍后我会帮你识别。”

### 6. 生成报告

提交前保存完整草稿，然后调用提交接口。

成功：

- 跳转报告页。
- 首页后续读取最新报告并派生今日建议。

失败：

- 保留草稿。
- 展示可重试错误。
- 不清空用户已填写内容。

## 最小完成标准

服务端当前 submit 所需最小结构：

- `basic` 存在。
- `style_goal.goals` 至少 1 个。
- `wardrobe.items` 至少 1 件。
- `style_goal`、`wardrobe` 结构存在。

因此首版前端的必填校验为：

- 至少选择或填写 1 个目标。
- 至少添加 1 件核心衣橱单品。

场景、禁忌和基础特征均可跳过。场景为空时服务端会使用默认“日常出门”。

## 跳过后的主界面状态

用户选择“先逛逛”后：

- 首页：显示“完成 3 分钟建档后解锁你的第一版建议”，提供继续建档按钮。
- 报告页：显示“完成建档后生成初版报告”，提供继续建档按钮。
- 衣橱页：显示“先添加 1 件核心单品”，提供继续建档按钮。
- 我的页：显示 onboarding 状态，并提供继续建档入口。

## 状态与错误处理

- 草稿保存中：禁用当前步骤主按钮，显示保存状态。
- 草稿保存失败：留在当前步骤，提示重试，不丢失本地输入。
- 报告生成中：显示生成中状态，避免重复提交。
- 报告生成失败：保留草稿，提示重试。
- 最新报告为空：服务端返回 `200` + `data:null`，前端展示空状态，不把它当成错误。

## 数据边界

- 用户输入的目标、禁忌、身材、发型、肤色、衣橱信息都视为敏感个人数据。
- 首版 onboarding 不要求用户上传自拍或衣橱照片。
- 文案避免“缺陷”“显胖”“不够好看”等羞辱式表达。
- AI 推断应在后续报告中以不确定性表达呈现，并允许用户反馈修正。

## 验收标准

- 首次无报告用户进入小程序时进入 onboarding 欢迎页。
- 用户可以跳过 onboarding 并进入主界面。
- 跳过后首页、报告、衣橱页均提供继续建档入口。
- 用户完成目标和至少一件核心衣橱后可以生成初版报告。
- 生成报告失败时草稿仍可恢复。
- 最新报告为空时不出现 404 网络错误。
- 页面不再展示本地 mock 建议作为真实内容。
