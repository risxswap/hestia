# 小程序「今日」页 UI 升级设计

日期：2026-06-19

## 背景

当前小程序已有“温和专业”的基础方向，但部分页面仍偏基础线框：米白背景、白色卡片、浅阴影能够保证克制，却不足以传达生活方式产品需要的温度、质感和私人顾问感。

本轮讨论确认：Hestia 面向有变美目标的普通用户，主体用户大概率是女生，也需要兼容少量男生。因此 UI 不应走粉色美妆工具、网红模板或冷淡审美手册路线，而应成为一个每天能打开、能给出具体建议的生活化私人形象顾问。

## 已确认方向

### 产品入口

底部 Tab 调整为：

```text
今日 / 聊聊 / 衣橱 / 我的
```

`今日` 是用户打开小程序后的第一心智：今天推荐我这样穿。

`聊聊` 不再承担首页主位，而是承担追问、换场景、拍照问搭配、解释原因和修改建议的入口。

### 首页定位

首页更名为 `今日`，首屏目标从“展示报告行动项”调整为“给出今天可直接执行的一套形象建议”。

用户第一眼应该获得确定感：

- 今天适合穿什么。
- 为什么这样穿。
- 如果不合适，怎么快速换场景或调整。
- 可以怎样反馈采纳、拒绝或实际体验。

### 视觉气质

核心方向是：

```text
生活化私人衣橱顾问
```

关键词：

- 温和。
- 可信。
- 生活化。
- 有审美但不端着。
- 具体可执行。
- 女性友好但不甜腻。
- 兼容男性用户，不做强性别化装饰。

推荐视觉语言：

- 背景：暖米白、暖灰白。
- 主色：深绿，用于主 CTA、关键状态和少量强调。
- 点缀色：低饱和金棕，用于避雷、解释、标签或细节。
- 卡片：暖白或微透明暖白，降低硬边界。
- 文字：深灰棕或接近黑色。
- 辅助文字：暖灰。
- 圆角：保持克制，按钮可胶囊化，内容卡片不宜过圆。
- 阴影：轻、软、低对比，用来制造层级，不制造悬浮堆叠感。

避免：

- 大面积粉紫渐变。
- 甜美贴纸感。
- 大图压倒内容。
- 过强营销感。
- 冷淡杂志感过重。
- 卡片嵌套卡片。
- 单一米色系导致页面发闷。

## 今日页首屏

### 页面目标

今日页首屏必须回答一个问题：

```text
今天我可以怎么穿？
```

首屏不做报告摘要，不做任务看板，不把对话框放成唯一主角。

### 首屏信息结构

首屏建议包含：

- 页面品牌或轻量标题：`Hestia` 或 `今日`。
- 场景与上下文：如天气、日期、用户选择的场景。
- 推荐标签：如 `今日推荐`。
- 推荐标题：一套明确方案，例如 `浅外套 + 直筒裤，轻松但有精神`。
- 一句话解释：说明适合的场景和避开的风险。
- 柔和照片氛围区：使用衣物、色彩、材质或生活场景图像，但不压过建议内容。
- 主 CTA：`照这个穿`。
- 次 CTA：`换个场景` 或 `想更正式一点`。

### 首屏文案风格

文案要像顾问说话，不像测评报告：

推荐：

```text
今天建议你穿得轻松一点，但线条要干净。
浅外套 + 直筒裤会比软塌针织更适合见客户后的晚餐。
```

避免：

```text
您的身材比例适合 X 型穿搭。
系统已根据参数生成最优推荐。
```

## 首屏下方内容

首屏下方展开完整顾问方案，但保持可扫读：

1. 为什么适合今天。
2. 上衣、下装、鞋包或配饰建议。
3. 发型方向。
4. 妆容或气色提示。
5. 避雷项。
6. 可替换单品。
7. 反馈入口。

反馈入口需要支持：

- 采纳。
- 不喜欢。
- 想改正式一点。
- 想改轻松一点。
- 实际穿了后的反馈。

这些反馈应进入长期记忆，优先级高于初始诊断。

## 照片和材质使用

确认采用 `柔和照片氛围`：

- 照片用于增加真实生活感和温度。
- 照片不作为首页压倒性的主视觉。
- 首页避免依赖大幅用户自拍或大幅参考图，因为用户上传质量不可控。
- 衣橱拼贴可用于衣橱页、搭配结果、报告详情中的局部模块。
- 参考明星或参考图只表达造型逻辑，不表达“你像谁”。

照片处理建议：

- 低饱和、暖调、轻柔对比。
- 允许用衣物局部、材质纹理、色彩组合替代人物大图。
- 图片容器比例稳定，避免加载后造成布局跳动。
- 用户未上传图片时，用色块、材质纹理或空状态替代，不用廉价插画。

## 页面关系

### 今日

承载每日明确建议和反馈闭环。

核心任务：

- 给出今天的一套推荐。
- 支持场景切换。
- 展示为什么适合。
- 收集采纳、拒绝和实际反馈。

### 聊聊

承载追问和修改。

核心任务：

- 文本提问。
- 拍照问搭配。
- 针对今日推荐追问原因。
- 要求换风格、换正式度、换单品。

### 报告

作为阶段性风格路线和行动项，不再抢首页首屏。

核心任务：

- 展示个人风格路线。
- 展示阶段性行动清单。
- 展示明星参考逻辑。
- 展示发型方向、穿搭原则、衣橱缺口和避雷项。

### 衣橱

承载真实单品和缺口，不做完整库存系统。

核心任务：

- 管理高频核心单品。
- 展示今日推荐用到了哪些已有单品。
- 展示缺口单品建议，但不提供具体商品链接。

### 我的

承载偏好、记忆、隐私和设置。

核心任务：

- 查看和修正结构化档案。
- 管理照片、反馈和记忆。
- 删除照片、档案和反馈数据。

## 组件方向

### 今日推荐卡

今日页核心组件。

内容：

- 上下文：天气、日期、场景。
- 推荐标题。
- 解释文案。
- 柔和图片或材质区。
- 主 CTA 和次 CTA。

状态：

- 有完整档案。
- 档案不足，需要补充信息。
- 今日无明确场景，使用默认生活场景。
- 用户拒绝后生成替代建议。

### 顾问解释模块

用于说明为什么适合。

表达原则：

- 先讲行动，再讲原因。
- 描述中性具体，避免羞辱和焦虑。
- 区分用户事实和 AI 推断。
- 推断带不确定性表达。

### 避雷模块

用于告诉用户今天不建议做什么。

表达原则：

- 用“今天不优先”替代绝对否定。
- 给出替代方案。
- 不评价身体缺陷。

### 反馈模块

用于形成记忆闭环。

建议入口：

- `照这个穿`。
- `不喜欢`。
- `换正式一点`。
- `换轻松一点`。
- `我实际这样穿了`。

反馈提交后，应明确告诉用户：

```text
已记住：你今天更喜欢利落但不强势的感觉。
```

## 设计风险

### 风险一：生活感变成网红模板

控制方式：

- 不使用高饱和粉色和大面积渐变。
- 不用过多装饰贴纸。
- 不让大图压过建议。
- 文案保持具体和顾问感。

### 风险二：首页建议不够确定

控制方式：

- 首屏必须给出一套明确推荐。
- CTA 使用行动语言。
- 允许快速换场景，但不要让用户先填表才能看到建议。

### 风险三：对男性用户不友好

控制方式：

- 主色不强女性化。
- 视觉语言以生活化和审美稳定为主，不以少女感为主。
- 推荐文案按用户目标和场景生成，而不是按性别刻板印象生成。

### 风险四：照片质量影响高级感

控制方式：

- 首页不依赖大图。
- 图片只作为柔和氛围层。
- 为缺图和低质量图准备材质、色块和单品局部替代方案。

## 后续实现建议

后续实现计划应优先处理：

1. 将底部 Tab 从 `首页` 改为 `今日`。
2. 重构今日页首屏为单套推荐结构。
3. 建立统一视觉 token：暖米白、深绿、金棕、暖灰、圆角、阴影。
4. 统一首页、onboarding、聊聊、报告的组件质感。
5. 增加今日推荐的反馈入口和记忆提示。
6. 验证小程序页面在常见手机宽度下文字不溢出、按钮不拥挤、内容不互相遮挡。

## 定稿结论

Hestia 小程序第一版 UI 应从“基础温和卡片”升级为“生活化私人衣橱顾问”。

首页改名为 `今日`，首屏直接给出“今天推荐你这样穿”的明确方案；照片只作为柔和生活氛围，不抢内容；对话入口用于追问和修改；完整报告作为阶段性路线沉淀。

这个方向能同时满足：

- 普通用户的低决策负担。
- 女生用户需要的生活温度和审美感。
- 男生用户也可接受的克制专业感。
- MVP 对每日建议、反馈和长期记忆的核心闭环。
