# Hestia 产品架构设计

日期：2026-06-19

## 背景

Hestia 是个人 AI 形象顾问 Agent，第一版首选载体是微信小程序。当前前端 UI 已按「今日 / 聊聊 / 衣橱 / 我的」方向实现，本设计不重新调整 UI，而是补齐产品架构：Hestia 如何同时覆盖发型、妆容、穿搭，并形成长期记忆与持续进化。

本轮确认的核心判断是：Hestia 不是一次性形象测评、不是完整衣橱库存系统，也不是电商导购平台。第一版应围绕一个持续闭环运转：

```text
轻量 onboarding
→ 初版形象路线报告
→ 今日完整建议
→ 用户反馈
→ 记忆更新
→ 下一次建议变准
```

## 产品架构

第一版采用：

```text
形象路线中枢 + 领域能力挂载
```

用户感知到的核心不是「发型工具、妆容工具、穿搭工具」三个分散入口，而是自己拥有最多 3 条可持续进化的个人形象路线。每条路线同时包含：

- 发型方向。
- 妆容方向。
- 穿搭策略。
- 适合场景。
- 避雷项。
- 明星或参考图的可迁移风格逻辑。
- 反馈权重。

产品主入口仍然是当前已实现的「今日」。每日建议输出一套可直接执行的完整形象方案，其中穿搭是主干，发型和妆容是配套层。报告页承载初版路线报告和阶段性复盘；聊聊页承载追问、拍照问搭配和修改建议；衣橱页维护核心单品；我的页承载档案、记忆、隐私和可修正内容。

## 形象路线模型

每个用户最多维护 3 条形象路线：

- 主路线：日常最高频，今日建议默认优先。
- 场景路线：用于约会、见客户、拍照、社交等特定场景。
- 探索路线：用户想尝试但尚未稳定确认的方向。

路线由 AI 先生成候选，用户通过「喜欢 / 不喜欢 / 想调整」轻量确认。确认后的路线进入推荐系统，后续由真实反馈持续更新路线权重、偏好、禁忌和策略记忆。

路线状态建议包括：

```text
candidate  候选路线
active     已确认并参与推荐
refinement 用户希望调整
paused     暂停推荐
archived   归档
```

路线示例：

```text
路线：利落亲和
目标感受：专业、轻松、有精神，不显得强势
适合场景：通勤、见客户、轻商务晚餐
发型策略：保持额头呼吸感，减少发尾厚重
妆容策略：干净底妆 + 眉眼清晰 + 低饱和唇色
穿搭策略：短外套、直筒裤、低饱和浅色层次
避雷：软塌针织、过甜裙装、过重卷发
参考逻辑：参考干净肩线和低对比色彩，不表达相貌相似
反馈权重：用户最近采纳较多，适合提升推荐优先级
```

## 核心数据流

主数据流固定为：

```text
Onboarding 输入
→ 信息抽取
→ 候选形象路线
→ 用户轻量确认
→ 初版路线报告
→ 今日完整建议
→ 用户反馈
→ 记忆更新
→ 下一次建议变准
```

### Onboarding 输入

Onboarding 收集生成初版路线所需的最小信息：

- 自拍或半身照。
- 核心衣橱照片。
- 基础事实。
- 风格目标。
- 风格禁忌。
- 常见生活和职业场景。
- 明星或参考风格。

自拍、衣橱、偏好和反馈都视为敏感个人数据，必须保留删除能力。

### 信息抽取

抽取 Agent 把对话和图片转成结构化信息，包括：

- 用户明确事实。
- AI 视觉推断。
- 核心衣橱单品。
- 发型条件。
- 妆容偏好。
- 穿搭约束。

AI 推断必须带不确定性，不能混同为用户事实。用户明确陈述和确认过的信息优先级高于 AI 推断。

### 候选形象路线

路线 Agent 生成最多 3 条候选路线。每条路线必须说明：

- 适合原因。
- 发型、妆容、穿搭的可执行方向。
- 适合场景。
- 避雷项。
- 明星或参考图中的可迁移风格逻辑。
- 不可迁移风险。

表达应强调「参考造型逻辑」，避免把核心结论写成「你像某明星」。

### 用户轻量确认

用户对每条候选路线点选：

- 喜欢。
- 不喜欢。
- 想调整。

喜欢的路线进入 active；不喜欢的路线降权或归档；想调整的路线进入 refinement，由对话继续补充原因和目标。

### 初版路线报告

报告不是测评结论，而是「初版形象策略板」。它应告诉用户：

- 当前 1-3 条形象路线。
- 每条路线的发型、妆容和穿搭原则。
- 现有衣橱可用组合。
- 当前缺口单品。
- 今天可以先做的行动。
- 明星或参考风格的可迁移逻辑。
- 避雷项。

### 今日完整建议

建议 Agent 根据当前场景、形象路线、天气、衣橱、偏好和历史反馈，输出一套完整建议：

- 穿搭主方案。
- 发型方向。
- 妆容或气色提示。
- 为什么适合今天。
- 今天不优先做什么。
- 可替换单品或替代方案。
- 反馈入口。

穿搭是每日建议主干，发型和妆容负责让整体形象方案成立。

### 用户反馈

每条建议都必须形成反馈目标。第一版至少记录：

- 采纳。
- 拒绝。
- 修改。
- 实际穿了。
- 外部反馈。
- 自由文本原因。

反馈进入长期记忆，真实使用反馈优先级高于初始诊断和参考风格匹配。

### 记忆更新

记忆 Agent 根据反馈更新：

- 事实记忆。
- 偏好记忆。
- 反馈记忆。
- 策略记忆。

策略记忆用户可见、可修正、可删除。展示时使用轻量表达，例如：

```text
我记住了：你在见客户场景里更喜欢浅色利落外套，不喜欢太正式的深色西装。
```

## 模块职责

### 用户体验层

```text
今日 / 聊聊 / 衣橱 / 我的
```

- 今日：承载每日完整建议和反馈闭环。
- 聊聊：承载追问、拍照问搭配、修改建议和解释原因。
- 衣橱：维护高频核心单品和缺口建议。
- 我的：承载档案、记忆、照片、反馈、隐私和删除。

### 业务中枢层

- 形象路线中枢：维护 ImageRoute 的生成、确认、权重调整和版本变化。
- 推荐编排器：把场景、路线、衣橱、天气、偏好和反馈记忆组合成建议任务输入。
- 反馈与记忆系统：把用户动作、原因和实际体验更新为可用记忆。

### 领域能力层

- 发型模块：负责发量、发质、脸型倾向、长度、层次、刘海、蓬松度、日常打理成本和场景正式度。
- 妆容模块：负责底妆质感、眉眼清晰度、唇色范围、妆感浓淡和气色方向。
- 穿搭模块：负责单品、廓形、颜色、材质、场景正式度和可替换方案。
- 明星/参考风格模块：负责可迁移造型逻辑和不可迁移风险，不做相貌对比。

MVP 先做领域模块，不做发型、妆容、穿搭三个独立子 Agent。用户体验上始终是一个统一的私人形象顾问。

### AI 任务层

第一版拆分为四类 AI 任务：

- 信息抽取：结构化用户事实、偏好、图片线索和衣橱信息。
- 路线生成：生成最多 3 条候选形象路线。
- 今日建议：生成基于场景的完整形象方案。
- 记忆归纳：从反馈中更新偏好、路线权重和策略记忆。

不要让大模型只依赖聊天上下文裸跑。关键用户信息必须沉淀为结构化档案和可审计的记忆。

## 核心数据对象

### UserProfile

用户基础画像，包括身高、职业或生活场景、风格目标、硬约束和摘要。第一版只保存当前档案，历史变化通过记忆和反馈追踪。

### ProfileFact

用户明确事实，记录用户说过或确认过的信息。例如「身高 165」「通勤场景多」「不穿高跟鞋」。

### ProfileInference

AI 推断，记录脸型倾向、肤色倾向、发量发质、比例线索和适合方向。必须包含 source、confidence，并允许用户修正。

### ImageRoute

形象路线中枢对象，包含路线名称、状态、权重、目标感受、适合场景、发型策略、妆容策略、穿搭策略、避雷项和参考风格逻辑。

ImageRoute 是推荐的中心对象。ProfileFact、ProfileInference、WardrobeItem 和 ReferenceStyle 都是路线和建议的输入，不直接成为用户第一心智。

### WardrobeItem

核心衣橱单品。只维护推荐所需的高频单品，不做完整库存系统。

### ReferenceStyle

明星或参考图风格样本。记录可迁移造型逻辑和不可迁移风险，不表达「你像谁」。

### Recommendation

一次建议请求和结果。记录场景、采用的路线、推荐方案、使用的衣橱项、发型建议、妆容建议、穿搭建议和生成上下文快照。

### Feedback

用户对建议的动作和原因。包括采纳、拒绝、修改、实际体验、外部反馈和自由文本。

### MemoryEntry

长期记忆，分为事实记忆、偏好记忆、反馈记忆和策略记忆。用户可见、可修正、可删除。

## 推荐生成逻辑

今日建议按以下顺序决策：

```text
1. 读取用户明确事实和隐私/禁用约束
2. 读取当前场景：天气、时间、地点类型、正式度、用户目标感受
3. 选择候选 ImageRoute：主路线优先，场景路线按匹配度提升
4. 读取高优先级记忆：用户重复采纳或拒绝过什么
5. 读取可用核心衣橱：优先用已有单品
6. 补全穿搭主方案
7. 补全发型和妆容配套建议
8. 生成避雷项和可替换方案
9. 记录 Recommendation 快照，等待反馈
```

优先级规则：

```text
用户删除/禁用要求
> 用户明确事实
> 真实穿着反馈
> 用户明确偏好
> 已确认 ImageRoute
> AI 推断
> 明星/参考风格逻辑
> 通用审美规则
```

## 反馈更新规则

### 采纳

提升该路线、单品、颜色、廓形、发型方向和妆容方向在相似场景中的权重。

### 不喜欢

记录或追问原因。如果原因明确，降低对应元素权重，而不是简单否定整条路线。

### 想改正式一点或轻松一点

更新该场景下的正式度偏好，不必改变整体路线。

### 实际穿了感觉不错

形成强反馈，优先级高于普通「采纳」。

### 实际穿了不舒服

形成强负反馈，必须影响后续推荐。

### 外部反馈

记录外部评价，但不绝对服从。如果外部评价和用户本人感受冲突，以用户本人感受为主。

### 策略记忆门槛

避免一次反馈就过度总结：

- 单次反馈记录为反馈记忆。
- 重复 2-3 次相似反馈后，归纳为策略记忆。
- 用户明确说「以后都不要」或「以后都可以」，直接形成偏好或策略记忆。

## MVP 范围

第一版必须支持：

- 对话式 onboarding。
- 上传自拍、半身照或核心衣橱照片。
- 抽取用户事实、AI 推断、偏好、禁忌和场景需求。
- 生成最多 3 条候选形象路线。
- 用户对路线轻量确认：喜欢 / 不喜欢 / 想调整。
- 生成初版路线报告。
- 基于真实场景生成今日建议。
- 今日建议包含穿搭主方案、发型方向、妆容或气色提示、避雷项和替换方案。
- 记录建议反馈：采纳、拒绝、修改、实际体验、外部反馈。
- 根据反馈更新事实记忆、偏好记忆、反馈记忆和策略记忆。
- 用户可查看、修正、删除长期记忆。
- 人工维护明星或参考风格库，只表达可迁移造型逻辑。

第一版不做：

- 完整电商导购或 SKU 推荐。
- 完整衣橱库存管理。
- 自动抓取明星图片。
- 把明星作为相貌对比系统。
- 复杂美妆教程、具体色号或产品推荐。
- 医疗、植发、皮肤病、整形、减肥等高风险建议。
- 保证变美或颜值提升的承诺。
- 未经授权公开复用用户照片或参考图。

## 妆容与发型边界

妆容第一版只做气色和场景妆容方向：

- 可以建议底妆质感、眉眼清晰度、唇色范围和妆感浓淡。
- 不做具体粉底色号、眼影盘、复杂步骤教学或功效型护肤建议。
- 不输出皮肤病、医美或需要专业资质的判断。

发型第一版只做方向建议：

- 可以建议长度、层次、刘海、蓬松度、打理方向和当天怎么梳。
- 不做植发、病理性脱发诊断、医疗护理承诺。

## 成功标准

第一版成功标准：

- 用户能在 8 分钟内完成 onboarding。
- 用户能理解并确认自己的 1-3 条形象路线。
- 用户每天能获得一套可执行的完整建议。
- 用户反馈能明显影响下一次建议。
- 用户能查看并修正「顾问记住了什么」。

## 待后续实现计划展开的问题

后续进入实现计划时，需要继续细化：

- ImageRoute、Recommendation、Feedback、MemoryEntry 的数据库字段。
- AI 任务输入输出 schema。
- 路线确认与反馈更新的接口设计。
- 我的页中记忆查看、修正、删除的最小交互。
- 管理端明星/参考风格库的数据维护流程。
