# 用户 Web 端 UI 设计

日期：2026-06-02

## 目标

本文档定义个人 AI 形象顾问 Agent 第一版 `user` 端的 UI 设计。

`user` 端是终端用户 Web 入口，定位为小程序的 Web 备份入口和分享访问入口。它不替代小程序主体验，不承载完整顾问聊天，不承载完整 onboarding，也不做完整衣橱管理。

第一版重点：

- 登录用户查看和复盘个人形象报告。
- 查看历史建议。
- 对已有报告和建议提交轻量反馈。
- 查看关键衣橱缺口。
- 通过独立分享页展示脱敏后的报告或建议摘要。
- 引导用户回到小程序继续提问和完成主要操作。

## 设计原则

### 小程序为主，Web 为辅

小程序仍然是主体验入口。用户 Web 端只做大屏阅读、复盘、轻反馈和分享。

Web 端第一版不支持：

- 发起新建议。
- 完整 AI 聊天流。
- 完整 onboarding。
- 完整衣橱管理。
- 上传和管理大量照片。

### 同风格，更适合阅读

`user` 端沿用小程序的温和专业视觉风格，但布局更适合浏览器阅读：

- 背景使用米白或暖灰白。
- 卡片使用白色或浅暖灰。
- 主色使用深绿。
- 辅助色使用暖棕、低饱和金棕。
- 文本使用深灰棕或接近黑色。
- 页面信息密度高于小程序，但避免仪表盘化。

### 隐私优先

Web 端可能出现在更开放的浏览环境，分享页也可能被外部访问，因此默认不展示敏感照片和详细画像。

敏感内容包括：

- 自拍和半身照。
- 衣橱照片。
- 详细脸型、体型、肤色、发量发质推断。
- 完整反馈历史。
- 完整个人档案。

## 信息架构

登录后导航使用 4 个主入口：

```text
首页 / 报告 / 建议 / 设置
```

分享页不进入登录后导航，使用独立路由。

建议路由：

```text
/                  首页工作台
/report            完整报告
/recommendations   历史建议列表
/recommendations/:id
/settings          设置
/share/report/:token
/share/recommendation/:token
```

## 首页工作台

首页采用个人工作台型布局。

### 页面目标

- 让用户快速看到当前最重要的形象行动项。
- 给用户一个大屏复盘入口。
- 提醒用户补充反馈。
- 引导用户回到小程序继续问顾问。

### 首屏结构

首屏最重要模块是最新报告行动项。

桌面端建议使用两栏布局：

- 左侧主内容：最新报告行动项。
- 右侧辅助内容：当前形象路线、最近建议、待反馈提醒或小程序入口。

移动 Web 使用单列布局。

### 顶部区域

顶部显示：

- 产品名称或 Logo。
- 导航：`首页 / 报告 / 建议 / 设置`。
- 用户头像或账号入口。
- `打开小程序` 主按钮。

### 当前形象摘要

显示用户当前形象路线摘要。

示例：

```text
当前路线：利落轻熟 · 低饱和 · 不甜腻
适合场景：通勤、客户会面、轻正式社交
```

该摘要不展示敏感照片和详细画像。

### 最新报告行动项

首页首屏展示最新报告中的 3 个行动项。

每个行动项包含：

- 行动标题。
- 简短原因。
- 避雷提示。
- 跳转完整报告的入口。

示例：

```text
1. 客户场景优先用利落外套
   避开太软塌的针织开衫。

2. 发型减少厚重感
   保留层次和额头呼吸感。

3. 补一件浅色短外套
   长度到胯上，线条干净。
```

### 最近建议

展示最近一次场景建议摘要。

内容包括：

- 场景。
- 用户目标。
- 推荐方案标签。
- 采纳状态。
- 查看详情入口。

如果最近建议没有反馈，显示轻量提醒。

### 待反馈提醒

Web 端支持对已有内容做轻量反馈。

待反馈模块展示：

- 未反馈的最近建议。
- 未确认的报告行动项。
- 简短 CTA：`补充反馈`。

反馈入口应简洁，不做完整聊天。

### 关键衣橱缺口

首页只显示 1-3 个关键缺口。

缺口只描述品类和特征，不给具体商品链接。

示例：

```text
浅色短外套
长度到胯上，线条干净，适合通勤和客户场景。
```

## 报告页

报告页用于完整阅读个人形象报告。

### 页面目标

- 提供比小程序更舒适的大屏报告阅读体验。
- 保持行动导向。
- 支持用户对报告模块提交轻量反馈。

### 页面结构

报告页按以下顺序组织：

1. 报告标题和更新时间。
2. 当前形象路线摘要。
3. 优先行动清单。
4. 风格路线详情。
5. 明星参考逻辑。
6. 发型方向。
7. 穿搭原则。
8. 现有衣橱可用组合摘要。
9. 关键衣橱缺口。
10. 避雷项。
11. 反馈入口。

### 行动清单

报告页首屏仍然优先展示行动清单，而不是长篇分析。

### 明星参考逻辑

Web 端展示明星参考时必须保持脱敏和边界：

- 只展示可参考的造型逻辑。
- 展示可迁移元素和不可迁移风险。
- 不写“你像某明星”。
- 不展示未经授权的明星图片作为核心内容。

### 反馈

报告页支持对模块反馈：

- 有用。
- 不像我。
- 想调整。
- 补充原因。

反馈提交后提示用户：反馈会用于后续建议优化。

## 建议页

建议页包含历史建议列表和建议详情。

### 历史建议列表

列表展示：

- 场景标题。
- 生成时间。
- 用户目标。
- 方案标签。
- 采纳状态。
- 是否已反馈。

支持基础筛选：

- 全部。
- 已采纳。
- 未反馈。

第一版不做复杂搜索和高级筛选。

### 建议详情

建议详情展示三方案对比，但不支持创建新建议。

每套方案包含：

- 方案标签，例如 `稳妥`、`更年轻`、`更正式`。
- 衣服组合。
- 发型建议。
- 适合理由。
- 避雷点。
- 可替代单品。
- 缺口提示。

### 反馈入口

每套方案支持：

- 采纳这套。
- 不喜欢。
- 想调整。
- 实际穿了之后反馈。

Web 反馈提交后，不进入完整对话流，只显示结果提示和回到小程序入口。

## 设置页

设置页承载账号、偏好、反馈和隐私控制。

### 页面结构

主要入口：

- 我的偏好。
- 反馈历史。
- 隐私与数据。
- 账号设置。

### 我的偏好

展示用户已确认的偏好和禁忌。

支持用户修改：

- 风格目标。
- 不喜欢的风格。
- 常见场景偏好。
- 颜色、版型、成熟度、露肤度等限制。

### 反馈历史

展示用户过去提交的反馈摘要。

第一版只做查看，不做复杂分析看板。

### 隐私与数据

隐私与数据是一级入口。

支持：

- 查看照片数据说明。
- 查看画像和 AI 推断说明。
- 查看反馈记忆说明。
- 请求删除照片。
- 请求删除画像。
- 请求删除反馈记录。
- 请求删除账号数据。

删除类操作应有明确确认流程。

## 分享页

分享页使用独立路由，不进入登录后导航。

第一版采用最小公开版。

### 分享页目标

- 让外部访问者理解这是一份 AI 形象建议摘要。
- 避免暴露用户敏感数据。
- 引导访问者生成自己的形象报告或打开小程序。

### 报告分享页

报告分享页可展示：

- 风格路线摘要。
- 脱敏后的行动建议。
- 部分穿搭原则。
- 部分发型原则。
- 可参考的造型逻辑。
- 产品引导 CTA。

报告分享页不展示：

- 自拍。
- 半身照。
- 衣橱照片。
- 详细脸型、体型、肤色等画像。
- 完整反馈历史。
- 完整衣橱缺口。
- 账号敏感信息。

### 建议分享页

建议分享页可展示：

- 场景标题。
- 脱敏后的推荐方案摘要。
- 方案意图标签。
- 部分穿搭和发型原则。
- 产品引导 CTA。

建议分享页不展示：

- 用户完整衣橱照片。
- 用户详细画像。
- 反馈历史。
- 未授权的敏感备注。

## 响应式规则

### 桌面端

桌面端优先使用宽屏阅读布局：

- 顶部导航。
- 内容最大宽度约束。
- 主要页面支持两栏结构。
- 重要行动项放在主列。
- 辅助状态和 CTA 放在侧列。

### 移动 Web

移动 Web 使用单列布局：

- 顶部导航收敛。
- 重要 CTA 固定在合适位置。
- 引导用户打开小程序继续操作。

移动 Web 不复制小程序底部 Tab。

## 组件规范

### 顶部导航

顶部导航保持克制：

- Logo 或产品名。
- 主导航。
- 打开小程序按钮。
- 用户入口。

### 行动项卡片

行动项卡片用于报告和首页。

内容结构：

- 标题。
- 原因。
- 避雷。
- 操作入口。

### 建议方案卡片

建议方案卡片用于建议详情。

内容结构：

- 方案标签。
- 推荐组合。
- 发型建议。
- 适合理由。
- 避雷点。
- 反馈按钮。

### 反馈控件

反馈控件保持轻量：

- 有用。
- 不像我。
- 想调整。
- 补充原因。

不要把反馈做成复杂问卷。

## MVP 验收标准

`user` 端 UI 设计满足第一版开发条件，当且仅当：

- 登录后首页采用个人工作台型。
- 首页首屏展示最新报告行动项。
- Web 端不支持发起新建议。
- Web 端不提供完整聊天流。
- 导航为 `首页 / 报告 / 建议 / 设置`。
- 报告页适合大屏阅读，并保持行动导向。
- 建议页支持历史建议查看和轻量反馈。
- 设置页提供隐私与数据一级入口。
- 分享页采用最小公开版。
- 分享页不展示自拍、衣橱照片、详细画像和完整反馈历史。
- 移动 Web 使用单列布局，并引导回小程序完成主体验。
