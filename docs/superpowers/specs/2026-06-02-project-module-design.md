# 项目模块设计

日期：2026-06-02

## 目标

本文档定义个人 AI 形象顾问 Agent 的第一版项目模块设计。项目包含一个 Go 服务端、一个管理端、一个微信小程序、一个简单的终端用户 Web 端。

第一版技术选型：

- 服务端：Golang
- 数据库：MySQL
- 缓存与队列：Redis
- 对象存储：七牛云 OSS
- 管理端：`admin`
- 小程序：`miniapp`
- 用户 Web：`user`
- 服务端：`server`

## 总体架构

项目采用一个 Go server 服务，不做微服务拆分。server 内部同时包含 HTTP API 和异步任务模块。

异步任务模块先作为同一个 Go 服务内的 goroutine/worker 运行，后续如果 AI 分析、报告生成、图片处理压力变大，可以平滑拆为独立 worker 进程。业务代码边界需要从第一版开始保留这种拆分可能。

整体结构：

```text
admin      管理端，用于运营配置、必要审核、任务监控
miniapp    微信小程序，承载主要用户体验
user       终端用户 Web，承载报告查看、历史建议、反馈和分享入口
server     Go 服务端，提供三端 API、业务编排、AI Gateway、异步任务
mysql      持久化业务数据
redis      缓存、限流、队列、短期任务锁
qiniu      图片和资源存储
```

## 前端应用边界

### miniapp

`miniapp` 是主用户入口，负责完整核心体验：

- 微信登录。
- 对话式 onboarding。
- 自拍、半身照、衣橱照片上传。
- 查看初版行动型形象报告。
- 发起每日场景穿搭和发型建议。
- 对报告和建议进行反馈。
- 查看和更新个人偏好。

### admin

`admin` 是管理端，第一版重点是运营配置、必要审核与任务监控：

- 明星风格库维护。
- 风格标签维护。
- 报告模板和提示词配置。
- 推荐规则配置。
- 用户基础信息查看。
- 图片、反馈、敏感内容的必要审核。
- 用户删除请求处理。
- 异步任务状态查看和失败重试。

第一版不做复杂数据看板和精细权限体系，但需要保留角色和权限扩展能力。

### user

`user` 是简单终端用户 Web 端，不替代小程序主体验：

- 查看个人形象报告。
- 查看历史建议。
- 提交轻量反馈。
- 通过分享链接查看授权范围内的报告或建议。
- 承载少量产品介绍、邀请和落地页能力。

`user` 第一版不做完整 onboarding、复杂衣橱管理和批量图片整理。

## 用户身份体系

三端共用同一套用户身份体系：

- 小程序通过微信登录建立主账号。
- 用户 Web 可以通过手机号验证码、微信授权或安全访问链接进入同一账号。
- 用户画像、衣橱、报告、推荐、反馈和记忆全部归属同一用户。
- 分享页可以支持临时访问 token，但只能访问被授权的有限内容，不能暴露敏感照片和完整个人档案。

管理端使用独立管理员身份体系，并通过角色控制管理能力。

## 服务端架构

服务端采用单体 Go server 和轻量领域分层架构。

不采用重型 DDD，也不做微服务拆分。第一版重点是让领域边界清楚、业务编排可读、基础设施可替换、异步 worker 可拆分。

推荐目录：

```text
server/
  cmd/
    server/                 # 服务启动入口
  internal/
    app/                    # 路由注册、依赖装配、任务消费者启动
    domain/                 # 领域模型和领域规则
      account/
      profile/
      asset/
      wardrobe/
      stylelib/
      report/
      recommendation/
      feedback/
      memory/
      job/
    application/            # 用例编排
      onboarding/
      daily_advice/
      report_generation/
      admin_ops/
      asset_ops/
    infrastructure/         # 外部依赖适配
      persistence/
      cache/
      queue/
      oss/
      ai/
      wechat/
      sms/
    interfaces/             # HTTP handler、DTO、middleware
      miniapp/
      admin/
      user/
      internal/
    pkg/                    # 不含业务语义的通用工具
```

分层规则：

- `domain` 存放业务概念、领域模型、核心规则。
- `application` 负责编排业务流程，例如 onboarding、报告生成、每日建议。
- `infrastructure` 负责 MySQL、Redis、七牛云、AI 模型、微信登录、短信等外部依赖。
- `interfaces` 负责三端 HTTP API、DTO、鉴权中间件和响应格式。
- `pkg` 只放不含业务语义的通用工具。

业务模块不应直接调用第三方模型、七牛云或 Redis。外部依赖需要通过 infrastructure 封装。

## HTTP API 边界

三端按入口拆 API，底层复用 application 和 domain。

```text
/api/miniapp/*    小程序主体验 API
/api/user/*       用户 Web API
/api/admin/*      管理端 API
/api/internal/*   内部任务、回调或诊断 API，默认不对前端暴露
```

### miniapp API

主要支持：

- 登录和账号绑定。
- onboarding。
- 上传凭证获取。
- 图片上传结果登记。
- 用户画像查看和修正。
- 衣橱核心单品管理。
- 报告生成和查看。
- 每日场景建议。
- 反馈提交。
- 用户数据删除请求。

### user API

主要支持：

- Web 登录或安全 token 访问。
- 查看报告。
- 查看历史建议。
- 提交轻量反馈。
- 分享页数据读取。

### admin API

主要支持：

- 管理员登录。
- 明星风格库管理。
- 风格标签管理。
- 提示词和报告模板管理。
- 用户基础信息查询。
- 内容审核。
- 用户删除请求处理。
- 异步任务查询和重试。
- AI 调用记录和成本摘要查看。

## 核心服务端模块

### account

负责用户账号、管理员账号、登录态和权限。

核心能力：

- 微信登录。
- 手机号绑定。
- Web 登录。
- 分享 token。
- 管理员登录。
- 管理端角色和权限。
- 用户注销和删除请求入口。

### profile

负责用户画像、偏好、禁忌和 AI 推断。

核心能力：

- 保存用户明确填写的基础信息。
- 保存 AI 推断的脸型、肤色、体型、发量发质等信息。
- 区分用户事实和 AI 推断。
- 支持用户确认、修正或删除画像字段。
- 维护风格目标、场景偏好、预算倾向和禁忌。

### asset

负责图片和文件资产。

核心能力：

- 生成七牛云上传凭证。
- 记录七牛云资源 key、bucket、mime、大小和来源。
- 管理自拍、半身照、衣橱图、参考图、明星风格样本图。
- 控制访问权限。
- 处理删除和软删除。
- 记录审核状态。

### wardrobe

负责用户核心衣橱。

核心能力：

- 管理核心单品。
- 记录分类、颜色、版型、材质、季节、正式度和场景标签。
- 绑定图片资源。
- 保存 AI 识别结果和用户修正。
- 标记是否核心单品、是否可用。

第一版不做完整库存系统，只支持生成建议所需的高频核心单品。

### stylelib

负责明星风格库和风格标签。

核心能力：

- 管理明星或参考对象。
- 管理风格样本。
- 管理风格关键词、场景、单品结构和发型方向。
- 记录可迁移元素。
- 记录不可迁移风险。
- 支持用户自选明星或上传参考图后的风格解析。

该模块是风格参考层，不是相貌对比系统。推荐表达应强调造型逻辑，不强调“用户像某明星”。

### ai

负责 AI Gateway。

核心能力：

- 统一 LLM 和视觉模型调用。
- 管理 prompt 版本。
- 管理模型配置。
- 支持结构化输出。
- 处理超时、重试和错误。
- 记录输入输出摘要。
- 记录成本、耗时和调用结果。

业务模块不能直接调用第三方大模型，必须通过 AI Gateway。

### job

负责异步任务。

第一版采用 Redis 队列加 MySQL 任务记录：

- Redis 负责排队、消费、重试触发和短期任务锁。
- MySQL 记录任务类型、状态、输入摘要、输出结果、失败原因、重试次数和关联对象。
- Go server 内部启动 worker goroutine 消费任务。

核心任务类型：

- 图片视觉识别。
- 衣橱单品结构化抽取。
- 用户画像结构化抽取。
- 参考图风格解析。
- 初版报告生成。
- 每日建议生成。
- 任务失败重试。
- 七牛云资源清理。

### report

负责个人形象报告。

核心能力：

- 创建初版行动型形象报告。
- 维护报告版本。
- 管理报告状态：生成中、成功、失败、已过期。
- 保存风格路线、发型方向、穿搭原则、衣橱组合、缺口建议和避雷项。
- 记录报告生成时使用的画像、衣橱和风格库快照摘要。
- 支持基于反馈刷新报告。

### recommendation

负责每日场景穿搭和发型建议。

核心能力：

- 接收场景输入。
- 读取用户画像、衣橱、明星风格参考和反馈记忆。
- 生成 2-3 套建议。
- 每套建议包含穿搭、发型、理由、替代方案、避雷项和缺口单品。
- 记录推荐生成所用上下文摘要。
- 为每条建议生成可反馈对象。

### feedback

负责用户反馈。

核心能力：

- 记录对报告、推荐、单品、发型和风格路线的反馈。
- 支持采纳、拒绝、修改、实际穿着结果和他人评价。
- 保存反馈原因。
- 触发记忆更新。

### memory

负责长期记忆和推荐修正。

核心能力：

- 从反馈中归纳长期偏好。
- 记录记忆来源和置信度。
- 支持记忆失效或被用户修正。
- 在后续推荐中提高真实反馈的优先级。

示例记忆：

- 用户不喜欢过甜风格。
- 用户客户会面场景偏好利落感。
- 用户接受低饱和色。
- 用户不接受过高露肤度。

### content_safety

负责内容安全和表达边界。

核心能力：

- 图片和文本审核结果记录。
- 敏感内容标记。
- 高风险建议拦截。
- 羞辱式表达、医疗诊断、整形承诺等输出约束。

### metrics

负责核心指标记录和基础统计。

第一版重点指标：

- 7 日留存。
- 14 日有效回访次数。
- onboarding 完成率。
- 报告满意度。
- 每日建议采纳率。
- 反馈提交率。
- 推荐修改率。
- 明星参考命中满意度。

## 基础设施使用约束

### MySQL

MySQL 存储持久化业务数据，包括用户、画像、衣橱、资产、风格库、报告、推荐、反馈、记忆、任务和审计记录。

关键 AI 输出不应只存在对话日志中，必须结构化落库。

### Redis

Redis 用于：

- 会话缓存。
- 短期验证码。
- 限流。
- 异步任务队列。
- 任务锁。
- 热点配置缓存。
- 短期推荐上下文缓存。

Redis 不作为关键业务数据的唯一存储。

### 七牛云 OSS

七牛云用于存储：

- 用户自拍和半身照。
- 衣橱照片。
- 用户上传参考图。
- 管理端维护的风格样本图。

服务端需要控制上传凭证、资源归属、访问权限和删除流程。

### AI Gateway

所有 AI 调用必须通过 server 内部 AI Gateway。AI Gateway 统一处理：

- 模型选择。
- Prompt 版本。
- 结构化输出。
- 超时和重试。
- 成本记录。
- 输入输出摘要。
- 错误审计。

## MVP 验收标准

模块设计满足第一版开发条件，当且仅当：

- 四个项目入口命名清楚：`server`、`admin`、`miniapp`、`user`。
- server 是单体 Go 服务，不做微服务拆分。
- server 内部具备异步任务模块，并预留 worker 独立部署边界。
- server 采用轻量领域分层，而不是大平层 CRUD。
- 三端 API 按入口拆分，底层复用 application 和 domain。
- MySQL、Redis、七牛云和 AI Gateway 的职责边界明确。
- 明星风格库被定义为风格参考层，而不是相貌对比系统。
- 用户反馈和长期记忆是推荐系统的核心输入。
- 用户敏感数据删除、AI 推断可修正、表达边界控制被纳入模块设计。
