# 小程序 UI 设计

日期：2026-06-02

## 目标

本文档定义个人 AI 形象顾问 Agent 第一版微信小程序的 UI 方向、信息架构和核心页面设计。

小程序是第一版核心用户体验入口。UI 应突出“随身私人形象顾问”的感受，让用户自然通过对话提问、上传照片、获得建议、提交反馈，并逐步建立长期形象记忆。

## 设计原则

### 顾问优先

小程序第一屏不是报告看板，也不是衣橱管理工具，而是 AI 形象顾问对话入口。用户打开后应立刻知道可以直接提问。

核心原则：

- 首页主体留给对话。
- 场景卡片只是输入辅助，不做首页主体。
- 报告、衣橱、偏好都服务于对话推荐。
- Agent 的进化感通过对话自然体现，例如“上次你说不喜欢太甜，这次我避开了”。

### 温和专业

视觉气质采用温和专业方向。

推荐视觉关键词：

- 私人顾问。
- 可信。
- 克制。
- 具体。
- 温和但不软弱。

视觉上避免：

- 过度网红化。
- 大面积粉紫渐变。
- 强营销感。
- 复杂看板感。
- 过度工具化和表格化。

推荐基础色彩：

- 背景：米白、暖灰白。
- 卡片：白色或浅暖灰。
- 强调色：深绿、暖棕、低饱和金棕。
- 文本：深灰棕或接近黑色。
- 辅助文本：暖灰。

## 全局信息架构

底部 Tab 使用 4 个入口：

```text
首页 / 顾问 / 衣橱 / 我的
```

### 首页

承载最新报告行动项、今日建议、档案状态和最近一次顾问结论。报告内容优先在首页首屏呈现，完整报告可作为二级页进入。

### 顾问

主操作入口。承载聊天流、拍照提问、场景建议、建议结果和反馈。

### 报告

作为首页下钻页面，承载个人形象报告、行动清单、风格路线、发型方向、穿搭原则、明星参考逻辑和衣橱缺口。

### 衣橱

承载核心单品管理。第一版不做完整库存系统，只维护推荐所需的高频核心单品和关键缺口。

### 我的

承载账号、偏好、反馈历史、隐私与数据、设置。

明星风格不做独立 Tab。明星风格参考应出现在报告和顾问建议中，作为造型逻辑参考，而不是独立内容消费入口。

## 顾问首页

顾问首页采用纯聊天优先布局。

### 页面目标

- 让用户直接向 AI 提问。
- 支持文本输入和拍照提问。
- 支持少量场景快捷 chip。
- 不让报告、衣橱、记忆状态抢占首页主体。

### 页面结构

顶部：

- 页面标题：`AI 形象顾问` 或产品名称。
- 右侧可放更多入口，如历史对话、设置或说明。

主体：

- 对话流占据页面主体。
- 新用户空状态由 AI 顾问气泡引导，例如：“今天想怎么呈现自己？你可以告诉我场景，也可以拍一件衣服问怎么搭。”
- 老用户对话中自然体现记忆，例如：“上次你说不喜欢太甜，我这次会避开柔美感太强的单品。”

输入区：

- 输入框固定在底部 Tab 上方。
- 左侧放加号或拍照入口。
- 右侧放发送按钮。
- 输入框上方可放 2-4 个横向快捷 chip，例如：`通勤怎么穿`、`拍照问搭配`、`约会建议`、`见客户`。

### 设计约束

- 不在首页顶部固定展示“已记住多少条偏好”之类状态栏。
- 不做大面积场景卡片宫格。
- 不把首页做成今日任务看板。
- 拍照入口必须明显，但不能压过文字提问。

## Onboarding

Onboarding 采用分步向导结构，但表达方式要保持顾问感，避免冷冰冰表单。

### 页面目标

- 8 分钟内完成初始画像建立。
- 收集生成初版报告所需的最小信息。
- 让用户理解为什么需要上传照片和衣橱。
- 给用户足够的隐私信任感。

### 步骤结构

1. 形象照片
2. 基础特征
3. 核心衣橱
4. 风格目标与禁忌
5. 明星或参考风格
6. 生成初版报告

### 步骤一：形象照片

收集自拍或半身照。

页面应说明：

- 照片用于生成个人形象建议。
- 不会公开展示。
- 用户后续可以删除。

### 步骤二：基础特征

收集：

- 身高。
- 体型感受。
- 肤色感受。
- 发量发质。
- 常见生活或职业场景。

AI 推断结果必须允许用户后续修正。

### 步骤三：核心衣橱

引导用户上传 10-20 件高频核心单品。

优先类型：

- 外套。
- 上衣。
- 下装。
- 鞋。
- 包。

不要求完整衣橱录入，不做库存压力。

### 步骤四：风格目标与禁忌

收集：

- 想呈现的感觉。
- 不想呈现的感觉。
- 不喜欢的颜色、版型、露肤度、成熟度。
- 高频场景的形象目标。

### 步骤五：明星或参考风格

支持：

- 选择喜欢的明星。
- 上传参考图。
- 描述喜欢的风格对象。

页面文案必须强调“参考造型逻辑”，避免暗示用户和明星相貌比较。

### 步骤六：生成初版报告

展示分析进度：

- 正在分析形象照片。
- 正在识别核心衣橱。
- 正在匹配可参考风格逻辑。
- 正在生成行动建议。

生成完成后进入报告页。

## 报告页

报告页首屏采用行动清单型。

### 页面目标

- 第一眼告诉用户接下来该做什么。
- 不是长篇测评。
- 先给行动，再解释风格路线和判断依据。

### 首屏结构

标题区域：

- `你的下一步`
- 显示报告更新时间和当前报告状态。

核心内容：

- 优先做的 3 件事。
- 每件事包含行动、原因和避雷提示。

示例：

```text
1. 客户场景优先用利落外套
   避开太软塌的针织开衫。

2. 发型减少厚重感
   保留层次和额头呼吸感。

3. 补一件浅色短外套
   长度到胯上，线条干净。
```

主 CTA：

- `按这个生成明天搭配`
- 或 `让顾问帮我搭一套`

### 下方详情

报告下方按模块展开：

- 当前风格路线。
- 明星参考逻辑。
- 发型方向。
- 穿搭原则。
- 现有衣橱可用组合。
- 衣橱缺口。
- 避雷项。
- 反馈入口。

### 明星参考展示

明星参考只表达造型逻辑：

- 可以参考的比例。
- 可以参考的色彩。
- 可以参考的发型方向。
- 可以参考的单品结构。
- 不建议照搬的风险。

避免把核心结论写成“你像某明星”。

## 建议结果页

建议结果页采用三方案对比。

### 页面目标

- 帮用户在真实场景中快速决策。
- 给足替代空间。
- 让反馈沉淀为长期记忆。

### 页面结构

顶部：

- 用户输入场景。
- 用户想呈现的感觉。

示例：

```text
明天见客户
目标：专业但不老气
```

方案区：

默认展示 3 套方案。方案命名应表达意图，而不是简单编号。

常见命名：

- 稳妥。
- 更年轻。
- 更正式。

不同场景可以替换为：

- 更松弛。
- 更有气场。
- 更亲和。
- 更适合拍照。

每套方案包含：

- 衣服组合。
- 发型建议。
- 适合理由。
- 避雷点。
- 可替代单品。
- 缺口单品提示。

### 反馈入口

每套方案都必须支持反馈：

- 采纳这套。
- 不喜欢。
- 想调整。
- 实际穿了之后反馈。

用户反馈后，Agent 应用对话回应，并提示已记住关键偏好。

## 衣橱页

衣橱页采用单品网格和关键缺口组合。

### 页面目标

- 让用户看到已录入的核心单品。
- 方便继续补充衣橱。
- 明确衣橱缺口如何影响推荐质量。
- 避免做成复杂库存系统。

### 首屏结构

顶部：

- 核心单品数量。
- 添加单品入口。
- 关键缺口提示。

中部：

- 分类筛选。
- 单品网格。

分类建议：

- 全部。
- 外套。
- 上衣。
- 下装。
- 鞋包。
- 配饰。

### 单品详情

单品详情展示：

- 图片。
- 分类。
- 颜色。
- 版型。
- 材质或厚薄。
- 季节。
- 正式度。
- 适合场景。
- AI 识别结果。
- 用户修正入口。

### 关键缺口

关键缺口以轻量提示出现，不抢占整个衣橱页。

示例：

```text
你现在缺一件浅色短外套。
它会提高通勤和客户场景的搭配质量。
```

缺口建议只描述品类和特征，不给具体商品链接。

## 我的页

我的页采用标准设置型。

### 页面目标

- 清晰承载账号和设置。
- 给用户明确的数据控制入口。
- 不把“记忆”做成我的页首屏主题。

### 页面结构

顶部：

- 用户头像。
- 昵称。
- 报告状态或账号状态。

主要入口：

- 我的偏好。
- 反馈历史。
- 隐私与数据。
- 账号设置。

### 隐私与数据

隐私与数据必须作为一级入口。

该入口下支持：

- 照片管理。
- 画像与 AI 推断查看。
- 反馈记忆查看。
- 删除照片。
- 删除画像。
- 删除反馈记录。
- 删除账号数据。

## 组件规范

### 对话气泡

AI 气泡使用浅暖灰背景，用户气泡使用深绿强调色。

气泡文本要具体、短句优先，避免长段解释。

### 快捷 Chip

Chip 用于输入辅助，不用于承载复杂内容。

常见 chip：

- 通勤怎么穿。
- 拍照问搭配。
- 明天见客户。
- 约会建议。
- 发型适合吗。

### 卡片

卡片用于报告行动项、建议方案、衣橱单品和设置入口。

卡片圆角保持克制，不使用过大圆角。推荐 12-16px。

### CTA

主 CTA 使用深绿。

常见 CTA：

- 开始生成报告。
- 让顾问帮我搭一套。
- 采纳这套。
- 拍照补充衣橱。

次级操作使用浅暖灰或文字按钮。

## 空状态

### 顾问首页空状态

用 AI 对话气泡引导，不用营销大字报。

示例：

```text
今天想怎么呈现自己？
你可以告诉我场景，也可以拍一件衣服问怎么搭。
```

### 报告页空状态

引导完成 onboarding 或补充必要资料。

### 衣橱页空状态

引导上传 10-20 件核心单品，强调“不需要完整录入所有衣服”。

## MVP 验收标准

小程序 UI 设计满足第一版开发条件，当且仅当：

- 首页呈现最新报告行动项。
- 底部 Tab 为 `首页 / 顾问 / 衣橱 / 我的`。
- 视觉气质为温和专业。
- Onboarding 是顾问式分步向导。
- 报告页首屏是行动清单。
- 建议结果页默认展示三套意图明确的方案。
- 衣橱页采用核心单品网格，并露出关键缺口。
- 我的页采用标准设置结构，并将隐私与数据作为一级入口。
- 明星风格参考不做独立 Tab。
- 所有用户反馈都能回到长期记忆系统。
