# 记忆记录管理设计

## 背景

“我的”页面中的记忆入口应进入可管理的长期记忆列表，而不是只展示统计摘要。用户需要逐条查看系统沉淀的记忆，并能删除不希望继续使用的记忆，或通过编辑纠正记忆内容。

## 范围

- 小程序 `pages/memory/index` 展示逐条记忆记录。
- 每条记忆支持编辑和删除。
- 后端新增用户态记忆接口，基于已有 `memories` 表，不引入完整来源图谱或版本对比。
- 删除使用软删除，确保后续推荐不再读取该条记忆。

## 接口

- `GET /api/user/memories`：返回当前用户可见、未删除的记忆记录。
- `PATCH /api/user/memories/:public_id`：更新用户可修正内容，包括 `memory_value`、`correction_note`，并记录 `user_corrected_at`。
- `DELETE /api/user/memories/:public_id`：软删除单条记忆。

## 展示规则

- 列表按更新时间倒序展示。
- 类型使用中性标签：明确事实、偏好、禁忌、AI 推断、待确认或其他。
- AI 推断需要展示低强度的置信度提示，避免把推断包装成事实。
- 空状态提示用户先完成 onboarding 或通过反馈逐步沉淀记忆。

## 不做

- 不自动抓取外部参考图或明星图片。
- 不提供复杂记忆来源图谱、版本回滚或合并。
- 不把记忆编辑扩展成完整档案编辑器；档案和偏好仍在独立页面管理。
